# AUDIT_ARTIFACT_POLICY — parabula-next

Status: planning/policy document only. No runtime files are changed by this file.

## Purpose

Define how generated audit outputs should be treated so the repository does not confuse source files with generated reports or workflow artifacts.

This directly addresses failures such as `rules-sync-check` expecting `meta/audit/recovery-audit.json` even when that file is generated by a script/workflow and may not be committed.

## Artifact categories

| Category | Meaning | Default handling |
|---|---|---|
| SOURCE | Hand-maintained source/config/rules file. | Commit and review. |
| GENERATED_COMMITTED | Generated file intentionally committed as repository state. | Commit only through documented script/workflow. |
| GENERATED_ARTIFACT_ONLY | Generated during CI/audit and uploaded as artifact. | Do not require committed presence. |
| GENERATED_LOCAL_ONLY | Generated during local diagnostics. | Do not commit by default. |
| HISTORICAL_REPORT | Old report preserved for context. | Keep, but mark as historical. |
| OPEN_GATE_REPORT | Report that identifies missing validation. | Keep until gate is closed. |

## Initial policy recommendations

| Path / family | Proposed category | Notes |
|---|---|---|
| `meta/audit/recovery-audit.json` | GENERATED_ARTIFACT_ONLY or GENERATED_COMMITTED — decision required | `recovery-audit.mjs` writes it; current rules-sync assumption is unresolved. |
| `meta/audit/generated-system-state.json` | GENERATED_ARTIFACT_ONLY by default | Produced by `generate-system-state-auto.mjs`. |
| `meta/audit/app-layer-check.json` | GENERATED_ARTIFACT_ONLY by default | Produced by `app-layer-check.mjs`. |
| `meta/audit/duplicate-audit.json` | GENERATED_ARTIFACT_ONLY by default | Produced by `duplicate-audit.mjs`. |
| `STATE/*AUDIT*.md` | HISTORICAL_REPORT or OPEN_GATE_REPORT | Classify per file date and relevance. |
| `STATE/*VALIDATION*.md/json` | OPEN_GATE_REPORT or HISTORICAL_REPORT | Must not override current source truth if stale. |
| workflow uploaded artifacts | GENERATED_ARTIFACT_ONLY | Should be cited by run ID if needed. |

## Rule for checks

Validation scripts must not fail merely because an artifact-only file is not committed.

Instead, they should distinguish:

1. required source file missing;
2. committed generated file missing;
3. artifact-only file not present locally;
4. stale historical report.

## Required update after policy approval

After this policy is approved, update or replace checks that assume generated audit outputs must always be committed.

Known affected script:

- `scripts/rules-sync-check.mjs`

## Success condition

The repository should make it obvious whether an audit output is:

- source of truth;
- generated committed state;
- workflow artifact;
- local temporary output;
- historical evidence.

No future AI session should treat all generated files as equally authoritative.
